## 4. 关于摘要（首页）

### 4.1 主段落

我是江中央，做语音、视频与网络传输约 18 年。从机顶盒、智能电视、IoT 通话，到直播连麦与实时云编辑，做的一直是要上线、要看大盘指标的实时系统。

曾在华为、中兴、TCL，以及阿里巴巴、字节跳动等国内大型公司一线落地。这些环境不仅重视功能能不能做出来，更重视首帧、成功率、卡顿、延迟等指标能否经得起海量用户与长期复盘——相关协议栈、弱网与跨 NAT、机型适配经验，是在真实大盘里反复验证过的，而不是停留在 Demo 能跑、协议名词会背的层面。

业余时间把这些年的一线经验沉淀为 **nexartc**：同一套低延迟、弱网与跨 NAT 的传输与交互能力，可落在工业控制、智能门铃、AI 语音交互、机器人遥操作等领域；云手机只是其中一种便于上手的体验与演示形态，用来验证端到端链路是否真的可感、可测。另一条线是面向嵌入式 Linux / RTOS 的极简 WebRTC 引擎 **RTNlite**。

我关心的不是 Demo 能跑通，而是弱网、跨 NAT、机型适配，以及长期稳定的线上指标。

**专业技能**

## 13. 延迟测试说明（定量）

对外主张（与简历一致，可坚持）：

| 场景 | 指标 | 数值 |
|------|------|------|
| 局域网 | glass-to-glass 端到端延迟 P50 | **&lt; 50 ms** |
| 电信公网 | glass-to-glass 端到端延迟 P50 | **&lt; 80 ms** |

### 13.1 定义

**glass-to-glass**：边缘真机屏幕内容变化（或注入后画面更新）→ 浏览器端可见对应帧的时间差，含采集、编码、传输、解码、渲染；**不含**人工反应时间。  
触控闭环可另注：`touch-down → 画面可见反馈` 与 glass-to-glass 同量级观测，不作单独对外数字除非另测。

### 13.2 拓扑（个人实测环境）

**局域网**

- 边缘：Android 真机跑 CAE，与客户端同一千兆/Wi-Fi LAN  
- 客户端：桌面 Chrome，打开 Web 控制台  
- 媒体：WebRTC（优先直连 / host–srflx）；无强制 TURN  
- 编码：H.264（设备 MediaCodec），分辨率与码率取演示常用档（如 720p 量级）

**电信公网**

- 边缘：家庭/机房宽带出口的 Android 真机（CAE）  
- 客户端：电信运营商接入的浏览器（同城或常见跨城个人链路）  
- 控制面：公网 Hub；媒体优先 P2P，必要时 TURN 中继（Mode A 边缘出站）  
- 其余编解码参数与局域网对照测试对齐，避免「换参数比延迟」

### 13.3 测量方法（可复现口径）

1. 在边缘屏显示高精度毫秒时钟，或浏览器叠加本地时钟与远端画面同屏拍摄/逐帧对照。  
2. 连续采样 ≥30 次有效样本；报告 **P50**（主数字），可选附 P95。  
3. 排除：首帧建连、ICE 收敛前、主动切分辨率/重协商、后台限帧时段。  
4. 站内只报个人环境结果，**不宣称**「任意网络保证 50/80ms」。

### 13.4 文案用法

- **Hero 压缩脚注（一行）**：  
  `实测：LAN P50&lt;50ms / 电信公网 P50&lt;80ms（glass-to-glass；个人环境，非全网承诺）。`  
- **作品详情展开**：用 §13.1–13.3 两三段；可链「复现说明」锚点 `#latency`。  
- **数字条 tooltip**：同 Hero 压缩脚注。
